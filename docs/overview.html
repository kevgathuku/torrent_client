Torrent Client — how it works (up to kog.11)

One supervised subtree per torrent: trackers and webseeds supply bytes, the coordinator plans rarest-first, one-shot workers download single pieces over the BEP-3 wire or HTTP Ranges, verified bytes land on disk. Built is running code; Planned is a tracked bead away.

1.Supervision tree

The application owns identity (a unique Registry) and a session supervisor. Each torrent gets its own subtree: an unnamed peer supervisor plus one coordinator that monitors every worker it starts. Workers are unnamed pids — IP alone is never an identity — and the coordinator reaps supervisor-restarted orphans so every live worker is coordinator-assigned.

flowchart TD APP["Application\nOTP entry"] --> REG["Registry (unique keys)\nper-identity addressing"] APP --> SESS["SessionSupervisor\nDynamicSupervisor"] SESS -.->|"session owns"| TS["TorrentSupervisor × N\none_for_one · 3 restarts / 60s"] TS --> PS["PeerSupervisor\nDynamicSupervisor · transient workers\n3 restarts / 10s"] TS --> COORD["Coordinator (transient)\n:normal = done, no restart"] PS --> W1["PeerWorker × N\nunnamed · one piece each"] COORD -.->|"monitors, assigns,\ncancels, reaps"| W1 ANN["Announcer\ninterval re-announce +\nbounded fan-out"] -.->|"supervised\nper torrent"| TS
Why one_for_one, not rest_for_one (ADR-0011 sketches the latter): with only two children and no ordering dependency, a coordinator restart must not kill in-flight workers — the new incarnation reaps stale ones on init and resumes from its own plan. The fuller tree (supervised re-announcer, multi-torrent session) landed in kog.10.

2.Component map

Domain — pure, no I/O Built

Torrent Built

Info-hash over raw info bytes, piece math (piece_span), announce tiers, trust-boundary validators. Pinned against fixtures.

PeerMessage Built

BEP-3 codec: per-message structs, length-prefixed encode/decode with error envelopes, 16 KiB cap, Cancel included.

PeerState Built

Per-peer posture (choke/interest + bitfield). Pure handle/2; selection reads plain index sets.

DownloadState Built

Per-torrent planning owned solely by the coordinator: rarest-first assign, in-flight set with endgame duplication, requeue, stall timestamps, completion.

Peer / Handshake Built

Compact + dictionary peer parsing; literal-only address parse (never DNS); 68-byte handshake with info-hash check.

Backoff / TierState Built

Pure re-announce backoff and tier failover walk shared by the announcer.

Effects — behaviour seams + real impls Built

Network Built

Raw :gen_tcp dial, 3s timeout. Workers take it via opts; tests substitute doubles.

Disk Built

Layout init, read/write_piece, resume codec wired since kog.10: staged temp-file + rename on every completion, distrusted reload on resume.

Clock / Socket / UDP / Requests Built

Time, socket, UDP transport, and HTTP tracker seams. Mox doubles in test; script sockets for wire tests.

Coordination Built

TorrentClient.Announcer Built

Interval re-announcer walking tiers (UDP via transport seam, HTTP via requests seam) + bounded whole-announce fan-out that merges peers as answers land.

TorrentClient.Coordinator Built

Owns all torrent state. Assigns pieces to idle peers, tracks worker outcomes, requeues on failure, skips poison peers, duplicates in endgame, restarts on stall, reports terminal states and stops :normal. Since kog.11: webseed fallback when no peer-held piece is assignable (peers always win).

TorrentClient.PeerWorker Built

One piece per process: connect → handshake → interest → 16 KiB requests (≤5 in flight) → SHA1 verify → disk write → report. Per-piece deadline; no retries, crash and let the supervisor decide.

TorrentClient.Session Built

Multi-torrent session (kog.10): owns the listen port, one stable peer-id, and a TorrentSupervisor per info-hash. Parses, lays out, and announce-fetches at add; pause/resume/forget/remove over hex id, prefix, or path; CLI via mix torrent.

TorrentClient.WebseedWorker Built

One piece per process over HTTP Ranges (kog.11, BEP-19): fetch → SHA1 verify → disk write → same coordinator reports as peer workers. Cancel drops bytes instead of writing; anything else stops abnormally.

TorrentClient.Webseed Built

Pure BEP-19 URL building (dir base plus name/path, verbatim single-file URL, unknown schemes skipped) plus the Range-fetch failover across bases. HTTP edge behind WebseedHttpBehaviour; the Tesla client follows archive.org 302s.

3.Peer acquisition (announce flow)

flowchart LR T[".torrent file"] --> B["Bento decode\ninfo-hash = SHA1(raw info bytes)"] B --> TIERS["announce tiers\nshuffled, failover order"] TIERS --> UDP["UDP announce (BEP-15)\nconnect → announce\nvia transport seam"] TIERS --> HTTP["HTTP announce\nbyte-wise encoded URL\n+ event/key, compact=1"] UDP --> RAW["compact peers\n6B v4 / 18B v6"] HTTP --> RAW2["compact peers\nor dict peers\nip/port text"] RAW --> P["Peer.parse_compact"] RAW2 --> Q["Peer.parse_address\nliteral only, never DNS"] P --> F["Peer.filter_usable\ndrop loopback / unspecified /\nlink-local / multicast\n(+ mapped judged by embedded v4;\nports 1..65535, compact port 0 dropped)"] Q --> F F --> SWARM["peer list\n→ coordinator"]
Trust boundary: tracker bytes are hostile input. Text addresses never touch DNS (hostnames are rejected, not resolved); anything undialable is dropped at ingress so it never reaches :gen_tcp.connect. Loopback peers still work in tests because fixtures construct %Peer{} directly, bypassing the filter.

4.Piece download (worker loop)

sequenceDiagram participant C as Coordinator participant W as PeerWorker (one piece) participant P as Peer (seed) participant D as Disk C->>W: start_child(peer, piece_index, piece_hash) W->>P: TCP connect + 68B handshake (info-hash check) W->>P: Interested + Unchoke P->>W: Bitfield / Have W->>C: {:availability, pid, MapSet} P->>W: Unchoke loop up to 5 in flight, 16 KiB blocks W->>P: Request(index, begin, length) P->>W: Piece(block) W->>C: {:block_progress, index} end W->>W: assemble + SHA1 verify W->>D: write_piece(base, info, index, data) W->>C: {:piece_complete, index} Note over W: exits :normal (transient: never restarted)
Failures are first-class branches, not exceptions: connect/handshake/protocol errors stop abnormally (supervisor restarts bounded by intensity; coordinator requeues + counts against the peer); a silent peer trips the per-piece deadline, publishes the missing set, and stops; a peer proven to lack the piece exits :normal and the coordinator records it missing. The webseed twin of this loop is one Range fetch per file slice (same verify → write → report), with cancel honored by a mailbox check before the write.

5.Endgame — duplicates race, loser cancels

sequenceDiagram participant C as Coordinator participant W1 as Worker 1 (held piece) participant W3 as Worker 3 (duplicate) participant S1 as Seed 1 (stalls last block) participant S3 as Seed 3 (fast) Note over C: needed empty, piece still out → endgame C->>W3: start duplicate of same piece W1->>S1: Request(blocks)... last block held S3->>W3: all blocks instantly W3->>C: {:piece_complete} C->>W1: send {:cancel_piece} (raw, mid-piece) W1->>S1: Cancel(index, begin, length) on the wire Note over W1: exits :normal (already verified elsewhere)
The cancel only works because the worker polls its mailbox each loop iteration (keepalives keep a stalled peer iterating) — and because finish/1 deliberately does not terminate losers first, which would win the race and swallow the Cancel.

6.Watchdog lifecycle

stateDiagram-v2 [*] --> Running: start, stamp progress Running --> Running: block_progress / piece_complete Running --> Stalled: quiet longer than budget Stalled --> Running: terminate, requeue, redial Stalled --> GivingUp: budget exceeded GivingUp --> [*]: report stalled/swarm_exhausted, stop normal Running --> [*]: all verified, report complete, stop normal
Give-ups are :normal stops with a report, never abnormal restarts — retry policy belongs to the session above. Stall detection runs on block progress, not piece completion, so one large piece on a slow link can't trip a sane deadline.

8.Reading guide

  • Start at lib/torrent_client/coordinator.ex moduledoc (the whole protocol in one page), then lib/download_state.ex (pure rules), then lib/torrent_client/peer_worker.ex (wire loop) and lib/torrent_client/webseed_worker.ex (HTTP twin).
  • test/coordinator_test.exs runs the full download against loopback seed doubles — the fastest way to see the system move.
  • Design rationale lives in docs/adr/ (supervision in 0011, wire codec in 0004, tracker protocols in 0003).
  • Domain purity is enforced by test/domain_purity_test.exs: the domain files make no effectful calls, ever.
